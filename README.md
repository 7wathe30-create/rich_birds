# Rich Birds — Voxel World

Воксельная карта земель, профиль с аватаром, подключение EVM-кошелька и серверный вход по подписи. **Покупки и выпуск NFT ещё не подключены.** Нет фиктивных балансов, локального присвоения земель или гостевого входа в курятник.

## Локальный запуск

Нужен **Node.js ≥22.13** (встроенный SQLite). Одна команда запускает интерфейс и API на одном порту:

```sh
npm ci
npm start
```

Откройте `http://localhost:3000`. SQLite автоматически создаётся в `data/rich-birds.sqlite`; каталог `data/` и `.env` исключены из git. После обновления проекта снова выполните `npm ci`.

Windows: `ЗАПУСК-НА-WINDOWS.bat`; macOS/Linux: `sh start-local.sh`. [Подробные шаги](docs/local-run.ru.md).

## Что работает

- Аватар занимает одну клетку: меняется вместе с масштабом карты, не перекрывает соседние земли.
- Иллюстративные воксельные портреты Виталика Бутерина, CZ и Майкла Сэйлора. Это не владельцы и не партнёры проекта.
- Кнопка «Купить участок» открывает состав покупки и её текущую недоступность. Не запрашиваются approve, перевод или оплата без контрактов.
- В маркете отдельные вкладки «Земли» и «Птицы». Земли представлены как каталог, не как несуществующие активные листинги.
- EIP-6963 / EIP-1193: выбор установленного EVM-кошелька, запрос подключения, добавление/переключение сети, отдельная подпись входа, отключение. При смене адреса/сети права сбрасываются.
- Одноразовый серверный challenge, проверка подписи, сессия в HttpOnly cookie, БД профилей. Ник и один из 15 аватаров либо своё изображение обязательны при создании профиля.
- Загруженное изображение повторно декодируется/перекодируется на сервере. Приватные ключи и seed-фразы не принимаются.
- API доступа в курятник проверяет `ownerOf` через RPC, адрес контракта, наличие bytecode и chainId; при отсутствии конфигурации, сессии или сбое RPC доступ закрыт.

## Сеть

По умолчанию **Robinhood Chain Testnet**, chainId `46630`, ETH для газа, официальный RPC `https://rpc.testnet.chain.robinhood.com`.

Официальная документация: https://docs.robinhood.com/chain/connecting/ и https://docs.robinhood.com/chain/add-network-to-wallet/ . Robinhood Chain — Ethereum-compatible L2, не Ethereum mainnet. Mainnet chainId `4663` задаётся только явной настройкой `CHAIN_NETWORK=mainnet`; это не включает продажи.

Для изменения настроек скопируйте `.env.example` в `.env`. Для развёртывания задайте точный `APP_ORIGIN` с HTTPS, собственный RPC и резервное копирование БД. Не помещайте RPC API-ключи в клиентские переменные.

## Ограничения этого этапа

Контракты коллекций и маркетплейса не созданы/не развёрнуты; выбор стейблкоина и удержания комиссии не утверждён. Индексатор NFT, реальные листинги, покупки, баланс NFT и размещение птиц ещё не подключены. `/api/lands` возвращает пустой список до индексатора, а не вымышленные NFT. Полная поддержка smart-contract wallets (EIP-1271) и мобильный WalletConnect — отдельный этап; сейчас нужны EVM-расширение и EOA-адрес.

Удалены активные сценарии локальной «примерки», передачи и сохранения владения в браузере. Старые демо-данные localStorage не мигрируют в настоящие профили и не дают прав.

## Проверки

```sh
npm test
npm run build
npm run avatars:generate
python3 scripts/generate-landmarks.py
```

Тесты проверяют геометрию клеток, каталог аватаров, проверку подписи/nonce, отказ чужому адресу и истёкшему challenge, серверное сохранение, отключение сессии и отсутствие неподтверждённых покупок/прав. Тестовая подпись не является доказательством отправки транзакции в публичную сеть; ничего не развёрнуто и средства не потрачены.

Исторические концепции `src/main.jsx`, `scene.jsx`, `canvas-renderer.js`, `style.css`, `demo-state.js` не используются как авторизация или владение текущего приложения. Технический план: [docs/profile-and-ownership.md](docs/profile-and-ownership.md).
